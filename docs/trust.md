# repo-pilot을 어디까지 믿을 수 있나 (3단계 기준)

측정 (2026-11-06, 대상 저장소 httpx):
- 검색: 3.4 개발용 질문 20개 + 봉인 질문 10개 (상위 5개 안에 정답 파일이 있으면 맞음)
- 에이전트: 3.6 개발용 질문 10개, 모델 fast(Groq gpt-oss-20b)

## 봉인 질문 결과 (번역 모델: long)
- 개발용 20/20 (100%) / 봉인 8/10 (80%)
- 같은 순서로 개선(50 → 60 → 80%) → 개선이 개발용 질문에만 맞춘 게 아님
- 놓친 2문제: q20(정답 목록이 좁을 수 있음, _urls.py도 관련 파일), q30(번역에 따라 흔들림)

## 믿고 써도 되는 경우
- **위치·이름 찾기** ("~는 어디에 정의돼 있나?", "어떤 예외가 나나?")
  - 에이전트가 grep이나 search_code로 찾고 read_file로 그 줄을 열어 확인한 뒤 답한다
  - 예: q02 기본 타임아웃 → `httpx/_config.py:246` (도구 2번 만에 정답), q04 TooManyRedirects → `httpx/_exceptions.py:249`
  - 에이전트 파일 일치 9/10(ReAct), 10/10(계획-실행)
- **질문에 코드 이름이 들어 있을 때** (`TooManyRedirects`, `raise_for_status` 등)
  - 검색 유사도가 0.83까지 올라가고 정답 파일이 1위로 온다
- **답에 `경로:줄`이 있고, 그 줄을 열어 보면 주장이 그대로 있을 때**

## 직접 확인해야 하는 경우
- **"없다", "지원하지 않는다"는 답**
  - q01 "연결 재시도는 어디서 설정하나?"에 "httpx에는 재시도 옵션이 없다"고 자신 있게 틀렸다(실제로는 `HTTPTransport(retries=...)`가 있다)
  - 못 찾은 것과 없는 것을 구분하지 못한다
- **답에 인용이 없거나, 에이전트가 열어 보지 않은 파일을 인용할 때**
  - 실제 사례: 검색 미리 보기에만 나온 `tests/client/test_redirects.py:252`를 근거로 댔다(read_file로 연 적 없음)
- **8단계를 다 쓰고 끝난 답** (`stopped: max_steps`)
  - 10문항 중 1~2건. 이때는 대부분 방향을 잘못 잡은 경우였다
- **한국어로만 묻는 동작 설명 질문**
  - 검색 단계에서 한국어 질문은 정답을 거의 못 찾았다(B-벡터 10/20). 에이전트는 스스로 영어 검색어를 쓰는 경우가 많아 덜하지만, 검색어가 한국어로 나가면 엉뚱한 결과가 나온다
- **여러 파일을 엮어야 하는 질문** (예: iter_lines가 _models.py와 _decoders.py를 함께 쓰는 경우)
  - 한 파일만 보고 답하기 쉽다
