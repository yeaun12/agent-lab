# Q1. 챗봇과 에이전트의 차이

## 5문장 요약

1. 챗봇은 질문을 받으면 모델을 **한 번** 부르고, 모델이 만든 글을 그대로 답으로 돌려준다.
2. 에이전트는 모델이 답 대신 **"이 도구를 이 인자로 실행해 달라"는 요청**(tool call)을 낼 수 있고, 코드가 그 도구를 실행해 결과를 대화에 붙인 뒤 모델을 **다시** 부른다.
3. 이 "모델 호출 → 도구 실행 → 결과 붙이기 → 다시 호출"을 모델이 더 이상 도구를 요청하지 않을 때까지 반복하는 것이 **도구 호출 순환**(agent loop)이다.
4. 모델은 도구를 직접 실행하지 못하고 요청만 한다. 실제 실행 여부와 권한은 내 코드가 정하므로, 인자 검증과 반복 상한 같은 안전장치도 코드 쪽에 둔다.
5. 그래서 에이전트의 품질은 모델만으로 정해지지 않는다. 도구 설명, 결과를 돌려주는 형식, 순환을 멈추는 규칙 같은 **주변 코드**가 함께 정한다.

## 내 코드에서 도구 호출 순환은 어디인가

| 역할 | 위치 |
|---|---|
| 순환 본체 | `scripts/tool_demo.py`의 `ask()` 안 `for _ in range(max_rounds):` |
| 끝내는 조건 | 같은 함수의 `if not result.tool_calls:` → 도구 요청이 없으면 `result.text`를 답으로 돌려준다 |
| 모델의 요청을 대화에 기록 | `"role": "assistant"`와 `"tool_calls"`를 담은 메시지를 `messages`에 추가 |
| 도구 실행 | `src/agent_lab/core/tools.py`의 `run_tool(name, arguments_json)` |
| 결과를 모델에게 돌려줌 | `"role": "tool"`, `"tool_call_id": call.id` 메시지를 추가 (어떤 요청의 결과인지 id로 짝지음) |
| 무한 반복 방지 | `max_rounds=5`: 5바퀴가 지나면 멈춘다 |
| 인자 실수 반복 방지 (1.6) | `MAX_FAILS = 2`: 같은 도구의 인자 검증이 2번 넘게 실패하면 더 묻지 않고 멈춘다 |

## 실제로 확인한 것

- 순환을 돌리면 "서울 날씨 알려주고, 그 기온을 화씨로 바꿔 줘"에 `get_weather` → `calculate`를 차례로 부르고, 받은 결과를 근거로 답한다. 도구 하나의 결과가 다음 도구의 인자가 되는 것은 순환이 있어야 가능하다.
- 1.6에서 인자가 규칙에 어긋나면(`city`가 1글자) `run_tool`이 실행하지 않고 `인자 오류: city ...`를 모델에게 돌려준다. 모델이 이를 보고 인자를 고쳐 다시 요청할 기회가 생긴다(`tests/test_tools.py`의 `test_run_tool_validation_error`).
- 실패를 예외로 끝내지 않고 **설명이 담긴 결과로 돌려주는 것**도 순환의 일부다(1.5 고쳐 보기 ②: 런던을 물으면 "가능한 도시: ..." 목록을 돌려줌).
